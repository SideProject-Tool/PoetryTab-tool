# 同步与数据完整规格（业务逻辑）

> 面向接手者：账号、同步、冲突、缓存、API、数据结构的全部行为规则。
> 用户可感知的行为描述见 `product-guide.md`；服务端实现在 `worker/src/worker.js`。
> **本文档是同步与数据契约的唯一权威**；README 数据契约节与 AGENTS 只保留摘要并链接到这里。

## 一、账号与认证

### 注册

1. 客户端生成随机 16 字节盐 → PBKDF2-SHA256(密码, 盐, 600,000 迭代) 派生 **authKey**
2. 提交 `{uid, salt, authKey, iter}`；明文密码永不出本机
3. 服务端校验 uid 字符集（2-32 位：字母/数字/汉字/`_`/`-`，不符返回 400；challenge/login 同规则），并校验 salt/authKey/iter 形状
4. 服务端以 **R2 条件写（仅当不存在时创建）** 落账号记录——并发同名注册只有一个成功，另一个收 409（409 = 该 ID 已被占用，属注册接口的设计行为）
5. 注册成功即发会话令牌；客户端随即以默认数据（含「我的收藏」空分组）首次保存落盘

### 登录（挑战应答）

1. `POST /api/challenge {uid}` → 返回一次性挑战（带签名、10 分钟有效）+ 该账号的盐与迭代数
2. 客户端重派生 authKey，以 `HMAC-SHA256(authKey, challenge)` 应答
3. `POST /api/login` 校验通过 → 发会话令牌 + 当前云端数据

**防枚举**：登录链路（challenge/login）无法探测 ID 是否存在——不存在的 ID 也返回 HMAC 确定性伪盐（响应形状与存在时完全一致），登录失败一律 401 统一文案。注册接口对已占用 ID 返回 409 是防抢注的设计行为，不在防枚举范围内。

### 会话令牌

- 形态：`uid|exp|HMAC(SYNC_TOKEN, uid|exp)`，**无状态**，30 天有效
- 之后所有数据读写凭 `Authorization: Bearer <令牌>`，uid 从令牌解析（无法越权读写他人数据）
- 登出时客户端删除本地 `pt.session` / `pt.uid`；令牌本身服务端无法吊销（无改密码功能；若未来增加，需为 SYNC_TOKEN 引入版本号使旧令牌失效）

### 账号自救与删除

- 无邮箱、无找回。**密码丢失 = 账号失联**（云端数据仍在但无法登录）
- 唯一自救：平时通过「导出备份」保存 JSON；「恢复备份」可在任意账号整份导入
- 数据删除：隐私页载明邮件申请渠道（见 `public/privacy.html`）；服务端执行 = 删除该 uid 的两组键：`pt/accounts/<uid>.json`、`pt/data/<uid>.json`（历史快照功能已下线，存量 `pt/data/<uid>/snap-*.json` 由每次保存顺手清空，无残留）

## 二、保存管线（客户端）

```
用户任意修改 → mutate（改本地状态 + 写缓存 + 置 dirty）
            → 快慢双通道调度（单飞保存队列，并发修改只落最新一份）
            → PUT /api/data（携带 X-Base-SavedAt 乐观锁，≤8MB 请求体）
```

- **快慢双通道**（控制云端请求量，见 `useCollection` 常量）：
  - **快层**（默认）：书签/分组/小部件/待办增删改、常规设置、重命名等 → 编辑静止 **3 秒**后落库；持续编辑期间**最长 30 秒**强制落库一次（编辑中的改动不会无限期悬空）
  - **慢通道**（`lazy`）：待办勾选、看板布局拖拽、卡片显隐等「最终一致即可」的改动 → **5 分钟**兜底落库；任何快层修改会**捎带**全部在途改动（整份覆盖模型下天然合并）
- 保存失败（网络）：状态条显示「未同步 · 自动重试中」，每 30 秒重发直到成功
- **超限（413）**：请求体超过 8MB 服务端返回 413；客户端进入错误态并**停止自动重试**（确定性失败重试无意义），提示「数据过大，请导出备份并精简」；用户精简数据后再次发生修改，即恢复正常保存管线
- 关页/切走标签页瞬间：`pagehide/visibilitychange` 兜底立即发送（请求体 ≤60KB 走 keepalive，超限退回普通请求尽力而为；此兜底请求不设超时）——**慢通道改动也不会因关页丢失**
- 其余 JSON 请求一律 15 秒超时，不会挂死在「保存中」
- 设置面板「上传到云端」= 清空全部定时器立即落库

## 三、同步状态机（版本、冲突与仲裁）

**版本号 = savedAt**（服务端签发的 ISO 时间戳，单调递增），同时作为 HTTP ETag。

PUT 必须携带客户端所知的版本（`X-Base-SavedAt`）；服务端用 **R2 条件写原子校验**——同版本并发只有一个成功。

本地缓存 `pt.cache = {uid, savedAt, dirty, fetchedAt, data}` 按 uid 隔离；`dirty` = 有未同步修改；`fetchedAt` = 缓存最近一次写入时刻（读云/编辑/广播采纳都会刷新）。

**核心不变量：仲裁完成前不存在任何静默覆盖云端的路径；本地未同步修改不丢。**

**启动新鲜窗**：打开新标签页时，若缓存在「启动校验频率」（settings.syncFreq，默认 10 分钟）内有过活动（`fetchedAt`）则**跳过启动校验**直接用缓存（省 Workers 请求配额）；云端若已被推进，首次保存携旧版本号 → 409 → 强制仲裁兜底，下表「启动恢复」各行在新鲜窗命中时顺延到首次保存时发生。

| 场景 | 行为 |
|---|---|
| 启动恢复：云端版本 = 缓存版本（304） | 沿用缓存数据（含未同步修改），防抖续传 |
| 启动恢复：云端已推进、内容与缓存一致 | 静默采纳云端 |
| 启动恢复：云端已推进、内容不同、本地有未同步修改 | **强制仲裁**（暂停自动保存） |
| 启动恢复：云端已推进、内容不同、本地无未同步修改 | 采纳云端 |
| 启动恢复：云端无数据 | 沿用本地未同步缓存；无则补默认数据并上传 |
| 登录成功：云端未被推进（版本 = 缓存版本） | 沿用本地缓存（含未同步修改），语义同 304 |
| 登录成功：云端已推进、内容不同、本地有未同步修改 | **强制仲裁** |
| 登录成功：云端已推进但内容一致，或本地无未同步修改 | 采纳云端 |
| 登录成功：云端无数据 | 沿用本地未同步缓存；无则补默认数据并上传 |
| 任意请求 401（会话过期/无效） | 清本地会话回登录门；缓存按 uid 保留；重新登录后按上面「登录成功」各行处理 |
| 保存 409，本地**无**未同步修改 | 自动拉取云端最新版并采纳，提示「已载入云端最新版本」 |
| 保存 409，本地**有**未同步修改 | **强制仲裁**：暂停自动保存，右上角徽标 + 设置面板提示，必须二选一 |
| 仲裁选「上传到云端」 | 以本地为准：借用云端当前版本号通过乐观锁，整份覆盖云端；若期间云端又被推进（再次 409）→ 刷新云端版本号、维持仲裁状态，再点一次即以最新版本重试 |
| 仲裁选「从云端恢复」 | 以云端为准：丢弃本地修改，拉取采纳 |
| 退出登录：本地无未同步修改 | 清会话回登录门；缓存保留（uid 隔离） |
| 退出登录：本地有未同步修改（非冲突态） | 先立即保存，成功后才退出；保存失败（离线等）提示并**中止退出** |
| 退出登录：处于冲突仲裁态 | **中止退出**并提示先解决同步冲突（复用设置面板仲裁 UI）——不允许借退出静默覆盖云端 |
| 切换登录其他账号 | 先走上述退出流程（含未同步检查），通过后新账号登录、缓存槽由新账号启用 |
| 同浏览器多标签页 | 保存成功经 BroadcastChannel 广播；**未编辑**的标签页即时采纳，**编辑中**的标签页保持本地、由下一次保存的 409 进入仲裁 |

## 四、本地缓存与离线

- `localStorage.pt.cache` 结构：`{uid, savedAt, dirty, data}`
  - **uid 隔离**：缓存为单槽，切换账号后由新账号启用（退出流程保证切换前旧账号数据已上传，见 §三）
  - **savedAt + dirty 持久化**：重启后能恢复乐观锁版本与「有未同步修改」的仲裁现场
  - **配额边界**：localStorage 写入失败（配额约 5MB，云端上限 8MB）时静默放弃持久化、仅内存持有，功能不受影响；代价是重启后丢失仲裁现场（dirty 标记与版本号）
- 启动拉取带 `If-None-Match`（上次 savedAt）：云端未变 → **304 零流量**，直接用缓存渲染
- 断网：缓存先行渲染，保存进入自动重试

## 五、API 一览

> CORS：`Access-Control-Allow-Origin: *` 全放行；自定义请求头（`Authorization`/`Content-Type`/`X-Base-SavedAt`/`If-None-Match`）走白名单，跨源开发环境可用。

| 端点 | 鉴权 | 限流（每分/IP） | 说明 |
|---|---|---|---|
| `POST /api/register` | 无 | 10 | uid/salt/authKey/iter 校验（不符 400）；条件写防抢注，已占用 409；成功返回会话 |
| `POST /api/challenge` | 无 | 30（与 login 合计） | 一次性挑战 + 盐；uid 非法 400；伪盐防枚举 |
| `POST /api/login` | 无 | 同上 | 挑战应答；签名/过期/重放校验（失败 400/401）；返回会话 + 全量数据 |
| `GET /api/data` | 会话 | — | 支持 `If-None-Match` → 304 |
| `PUT /api/data` | 会话 | — | ≤8MB 请求体，超限 **413**；`X-Base-SavedAt` 乐观锁（R2 CAS 原子） |
| `GET /api/favicon?domain=` | 无 | 600 | 图标代理：Google s2 → DDG 兜底，R2 缓存 30 天；浏览器缓存命中 30 天、404 负缓存 1 天（重复打开零请求） |
| `GET /api/title?url=` | 无 | 120 | 网页标题代理：读前 256KB、10s 超时、R2 缓存 30 天；浏览器缓存命中 7 天、404 负缓存 1 天 |
| `GET /api/health` | 无 | — | 存活探测 |

## 六、数据结构（云端 `pt/data/<uid>.json` 的 `data` 字段）

**服务端契约**：Worker 把 `data` 当不透明 JSON 存取——只校验体积与顶层 `folders` 为数组，不解释内部字段；对旧版客户端保持读写兼容（字段只增不改义）；字段缺省/畸形的兼容归一由客户端 `ensureShape` 单点负责。

### 字段、默认值与枚举

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `v` | number | `1` | schema 版本号，只增不改义 |
| `folders` | Folder[] | `[「我的收藏」空分组]` | 分组树（顶层卡片，每张分组卡一张） |
| `iframeWidgets` | Widget[] | `[]` | iframe 小部件卡 |
| `todoWidgets` | TodoWidget[] | `[]` | 待办清单卡 |
| `historyWidgets` | HistoryWidget[] | `[]` | 浏览历史卡（仅卡片实例；历史数据仅本机读取，不入云） |
| `settings` | Settings | 见下表 | 随账号同步的偏好 |
| `poemLib` | PoemLib | `{custom:[],hidden:[],edits:{},rev:0}` | 用户词库修改（自定义词条 / 隐藏的内置词条 / 内置词条覆盖编辑），见下节 |
| `layout` | Layout | `{v:2, cols:[[],[],[],[],[]]}` | 布局，固定 5 槽位 |

- `Folder = { id: "f_*", title, children: (Bookmark|Folder)[] }`；`Bookmark = { id: "b_*", title, url, favicon?, dateAdded }`
- `Widget = { id: "iw_*", title, url, h? }`；`h` = 卡片高度像素（缺省 420，可调 200-2000）
- `TodoWidget = { id: "td_*", title, items: TodoItem[] }`；`TodoItem = { id: "ti_*", text, done, createdAt }`。条目**存储顺序**与显示无关：显示时未完成在前、已完成在后（各自保持存储序，即「完成沉底」）；卡内拖拽排序只重排未完成组
- `HistoryWidget = { id: "wh_*", title, h? }`；`h` = 卡片高度像素（缺省内容自适应、列表 420px 内滚，可设 200-2000，设定后列表填满剩余空间）。**仅卡片实例入云**：历史记录经 `chrome.history` 在本机实时读取展示（扩展版），任何浏览记录都不写入云端 data
- 结构上 Folder 可嵌套任意层（书签导入可产生任意深度）；UI 只创建/展示「分组 + 一级子分组」两级，更深层经浏览浮层只读查看

### poemLib（用户词库）

- `PoemLib = { custom: PoemEntry[], hidden: string[], edits: { [uuid]: PoemPatch }, rev: number }`
- `PoemEntry = { uuid: "u_*", cat: <12 类 key>, content, author, source }`；`content` 必填非空，`author`/`source` 可为空字符串（`u_` 前缀保证不与内置 UUID 冲突）
- **内置语料只读**：删除内置词条 = 把 uuid 写入 `hidden`（可随时恢复）；修改内置词条 = 把三字段整值写入 `edits[uuid]` 覆盖显示，原始语料不变、语料包升级后覆盖仍生效。自定义词条的增删改直接作用于 `custom`
- `rev` 每次词库修改 +1：诗词引擎据此感知变化并重新洗牌（新增 / 删除 / 隐藏 / 恢复会改变轮播集合）
- **轮播合并规则**（`contentEngine.getContentByCategories`）：内置列表 → 剔除 `hidden` → 命中 `edits` 的按三字段覆盖 → 追加已启用分类的自定义词条；再经与内置相同的去重规则（内容相同只保留一条）
- 归一：`ensureShape` 经 `normalizePoemLib` 兜底——非数组/畸形条目剔除、字段取字符串、`content` 为空的词条丢弃
- Worker 不解释该字段（不透明 JSON，顶层只校验 `folders`）；体积受整份 8MB 上限约束

### 布局语义

- **5 槽位为存储上限**：设备按自身列数 N 取前 N 列，第 N 槽之后的溢出内容并入末列显示
- 列内顺序即卡片顺序；手机单列按「槽位序 × 列内序」排列
- **写回规则**：拖拽保存时，本设备把可见 N 列依次写入槽位 0..N-1，溢出内容并入第 N 槽，其后槽位清空。用户可见后果：**在窄窗口/手机上发生拖拽保存后，宽屏多列的分布会被合并重排为拖拽设备的列数**（列式模型的既定取舍）
- 隐藏卡片不占槽位；「隐藏→再显示」位置不变（隐藏期间若发生过拖拽写回，则落到最短列尾）
- **v1 兼容**：旧版显式坐标数组（`[{i,x,y,w,h}]`）加载时自动按阅读顺序迁移为列式，启动检测到旧格式即回写 v2；旧客户端读到 v2 会优雅降级为自动排列

## 七、已知边界（设计取舍）

- 同步为**整份覆盖**模型（无字段级合并）——多设备冲突只能整份二选一，由强制仲裁兜底
- **启动新鲜窗内不校验云端**（间隔 = settings.syncFreq，默认 10 分钟）：其他设备的修改最迟一个间隔后可见（或设置面板「从云端恢复」手动拉取）；期间的跨设备冲突由首次保存的 409 强制仲裁兜底，不丢数据、不静默覆盖
- 会话令牌不可吊销、无改密码
- 单份数据 ≤8MB（请求体）；客户端不做预检，超限按 §二「413」行为处理
- favicon/title 代理对任意公网站点抓取（仅读 title 标签 / 图标，不执行内容）；私有网络地址经 Cloudflare 边缘不可达；代理缓存无总量上限（写入速率受每 IP 限流约束，个人规模存量可忽略；如需硬上界，可在部署机为 `pt/favicons/`、`pt/titles/` 前缀配置 R2 lifecycle 过期规则，零代码）
- 跨 isolate 同毫秒写入理论上可能产生重复 savedAt（ETag 碰撞 → 一次陈旧 304）；CAS 保证数据不被覆盖，概率极低
- 书签磁贴的图标经代理缓存 30 天，源站换图标最长一个月后刷新
- 网页版（https）下 iframe 嵌 http 站点会被浏览器混合内容策略拦截（卡片菜单「新窗口打开」兜底）
